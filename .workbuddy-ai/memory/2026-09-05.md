# 2026-09-05

## 新增插件 fal-minimax-h3-max 1.0.0

`plugins/tasks/fal-minimax-h3-max/1.0.0/{plugin.js,test.js}`，接入 fal.ai MiniMax H3 Max 视频三个队列端点：
`minimax/h3-max/{text-to-video,image-to-video,reference-to-video}`。channelType 分配 `10005`，author `Jushenzhidao`。

- 原生路由 `/fal/minimax/h3-max/{route}` 走同构直通（body 与 fal input schema 逐字段一致，仅剥离 `model`）；
  `openai_video` 协议入口走异构（seconds→duration、size→resolution、input_reference→image_url、
  metadata 白名单→reference_*_urls / aspect_ratio / seed 等），共用单一 encoder。
- 查询固定打 fal response 端点 `/{app}/requests/{id}`（不含 route 段），进行中 = 400 + `detail.type=request_in_progress`。
- 合同测试 89 项全通过（`node --check` + 纯函数测试，无网络调用）。

## 未接入：director 端点

`minimax/h3-max/director` 是 WebRTC 实时会话端点（configure/prompt/ping/stop 消息 + 视频音频轨道），
没有 request_id、没有轮询语义，异步任务插件模型不适用。已在技能中记录该判定依据。

## 新增插件 fal-minimax-v2 1.0.0（异构桥）

`plugins/tasks/fal-minimax-v2/1.0.0/{plugin.js,test.js}`，channelType `10006`。
与 fal-minimax-h3-max 同一 fal 上游，但**入口换成 MiniMax 官方 /v2 契约**（跨协议异构桥）：

- 路由镜像官方路径：`POST /fal-minimax/v2/video_generation`、`GET /fal-minimax/v2/query/video_generation/:task_id`；
  客户端模型名 `MiniMax-H3-Max`。
- 入站 `content[]` 多模态数组（type + role）→ 内部规范模型 → fal 扁平字段
  （image_url / end_image_url / reference_{image,video,audio}_urls）；端点按 content 形态推断三选一。
- `ratio` 按官方三场景语义分别处理：t2v 必填非 adaptive；i2v 忽略具体值（fal 无该字段）；r2v 默认 adaptive。
- 能力缺口显式拒绝：MiniMax-H3、2K、duration 4、callback_url、aigc_watermark:true、仅尾帧生成。
- renderer 还原官方响应形状：创建严格 `{ task_id }`；查询 `{ task: {...} }` + status 枚举
  queued/running/succeeded/failed/cancelled；时间戳归一为秒。fal 不回报用量故省略 `task.usage`。
- 合同测试 107 项全通过。

## 技能更新

`new-api-task-plugin-builder` 新增两个小节：「fal.ai 队列协议适配经验」（Key 鉴权、response vs status 端点选择、
requests URL 只保留 owner/app、detail 三形态、sync_mode data URI 不注册 artifact、realtime 端点不可接入）
与「MiniMax /v2 官方入口 → fal 上游异构桥」（content[] 角色映射、ratio 三场景语义、媒体值三形态、
能力缺口显式拒绝清单、两端约束取交集、renderer 还原官方形状）。channelTypes 登记表补齐 10004/10005/10006。
