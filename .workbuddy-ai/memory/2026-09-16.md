## senseaudio-video 真实 e2e（拿到用户 API Key 后补跑）

- **错误信封实测**：`HTTP + {code, message, ref_code?, ref_scope?}`，`code` 是**字符串 slug**
  （有时直接就是中文提示本身），`ref_code` 才是数字码；成功体不带 `code`。
  401 `authentication_error` / 400 `图片链接无效` / 400 `图片高度不符合要求` /
  404 `notfound` + `ref_code 404000` + `ref_scope: "common"`。
  原以为会是火山方舟同构的 `{error:{code,message}}`——**不是**，但现有 `upstreamError()`
  的 `code`/`message` 分支恰好覆盖，零改动通过。
- **创建响应**：`{"task_id":"<uuid>"}`。**查询响应**：与文档一致，`duration` 回显请求时长；
  `status=pending` 时 `progress` 已经是 **50**（所以 QUEUED 也会带 50%，照实透出不覆盖）。
  终态 `completed` 时顶层给 `video_url`，`provider_specific` 里被上游**回填** `watermark_url`。
- **素材在 create 阶段就校验**：可达性 + 尺寸（高度 <300px 直接 400）。插件无法预取素材。
- 端到端结果：**四种模式全跑通**（5 个真实任务）——
  文生视频 10s/720p（12 轮，6.2MB）、图生视频 first_frame 5s/720p（10 轮，4.4MB）、
  首尾帧 first_frame+last_frame（14 轮，3.9MB，`action=first_tail_to_video`）、
  参考图 reference×2（18 轮，2.7MB，`action=reference_to_video`）。
  全部走完 decode → submit → poll → 终态 → 制品 → 回源下载 → native 渲染。
- **零成本参数校验**：拆 MP4 box 确认四个成片都是 `isom` + `avc1` 1280×720 + `mp4a` 音轨，
  `mvhd` 时长与请求一致 → `resolution`/`duration`/`generate_audio` 三个参数**真的生效**，
  不只是上游回显。已固化成技能资产
  `.workbuddy-ai/skills/new-api-task-plugin-builder/assets/media-probe.py`（零依赖，
  读 ftyp/mvhd/trak/hdlr/stsd，没有 ffmpeg 也能用；顺带嗅探 PNG/JPEG/WAV/MP3 等）。
- **结果 URL 形态由 watermark 决定**：`true` → `/video_add_watermark/<uuid>/<uuid>.mp4`；
  `false` → `/video/<uuid>`（**没有扩展名**）。制品类型不能靠扩展名推断。
- 仍未验证：失败终态（`status=failed` + `error_message`，不想故意触发违规内容）、
  参考音频/参考视频元素（只跑了参考图）。
- 可用的合规测试图：`https://fastly.picsum.photos/id/415/1280/720.jpg?hmac=...`（1280×720 JPEG 58KB）。
  上游自己 CDN 的 `logo2.png` 是 379×158，**高度不够 300px** 会被拒。

**本次修掉的两个真缺陷（live-harness.mjs）**：

1. 失败分支原来是裸 `process.exit(1)` → 闸门解析不到用例。**闸门对此有 `__process__` 兜底**
   （"进程未产生任何可解析结果"直接判 FAIL），所以不是静默 PASS，而是**真实层永远拿不到 PASS**——
   第一次带 `--include-live` 跑闸门就撞上了：live 脚本 3m14s 正常出片、exit 0，但输出里
   没有 `✓/✗` 行也没有聚合数字，被判 `__process__` FAIL。
   已改为所有失败分支走 `fail(label, detail)`（记失败用例 + `t.done()`）；
   成功分支把拿到 task id / 轮询终态 / 结果 URL / 制品 / `credentialless` / 下载落盘记成用例。
2. 修 1 之后 `--dry-run` 分支踩到新坑：`t.done()` 只在有失败时退出，dry-run 会**继续真的提交任务**。
   已补 `process.exit(0)`。教训：**「跑完就该结束」的分支不能只依赖 done() 收尾**。
- 另外 testkit 的 import 路径要兼容两种位置（复制到 tmp-tests 后走 `../skills/...`，

## 脚手架修正（live-harness.mjs）

`--entry native` 原来写死调 `plugin.native.submit(ctx)` 当请求用，有两个问题：
① 真实插件的 decode 成员按路由语义命名（`createTask` / `create3D` / `textVideoV3`），根本没有 `submit`；
② native decode 返回的是 canonical intent（`{kind,model,action,requestBody}`），不是请求对象。
已改为：从 `meta.routes` 里那条 `type:"submit"` 路由读 `decode` 名字（回退 `submit`），
取 intent 的 `requestBody` 塞进 `ctx`，请求一律由 `buildSubmitRequest` 构建。

## 测试报告 + 回归闭环（新增基础设施）

按用户要求搭了「每次测试落报告 → 倒排索引 → 修复后与历史报告比对 → 闸门」的端到端闭环。

新增文件：
- `.workbuddy-ai/tools/test-runner.mjs`：跑测试 → 生成报告 → 重建倒排索引 → 逐用例与历史比对 → 输出闸门结论。
- `.workbuddy-ai/skills/new-api-task-plugin-builder/assets/testkit.mjs`：可选的用例级测试工具
  （`createSuite()`，输出人读行 + 结构化块，显式声明 key/version/layer）。
- `.workbuddy-ai/test-reports/`：报告库。`INDEX.md` 倒排总表、`index.json` 机器可读倒排（reports[0] 最新）、
  `LATEST.md` 全插件最新摘要、`<key>/<ts>-<key>-<ver>-<layer>.md` 不可变报告、`<key>/LATEST[-<layer>].md` 最新副本。

关键设计决定：
- **闸门按插件聚合**，不按单层。最初按单层判定，导致 aivideomaker 的 spec 层因为「本次没跑 contract」
  被误判 INCOMPLETE；改成同一次运行里该插件所有层合并判定。
- **退出码分级**：FAIL=1 / INCOMPLETE=2（不算完成）/ PASS=0。INCOMPLETE 用来表达
  「离线层过了但真实层没验」，正好落实 skill 里「离线全绿 ≠ 完成」的规则。
- **层覆盖只看本次实际跑过的层**，历史验过的层不顶替本次复验（否则改了插件重跑离线就能假 PASS）。
- **容错解析三种历史输出**：结构化块 > `✓/✗/⚠ label` 行 > 聚合数字（`ALL PASS: N` / `FAILED n (passed m)` /
  `passed=n failed=m`）。老脚本只输出聚合时，回归降级为「通过数下降/失败数上升」判定，报告标注「仅聚合」。
- 为 acedata-suno / kling / aivideomaker.test / aivideomaker.openapi 四个老脚本的断言辅助函数插了
  `mark()` 打印（带 `// 用例级输出：… 勿删` 注释），把回归精度从聚合提升到用例级。**只加打印，不动断言逻辑**。
- 报告头部钉死被测源码 sha256 + 脚本 sha256，解决「这份报告验的是哪一版代码」的歧义。
- 索引自愈：报告文件被删则索引项下次自动剔除（演练残留就是这么清掉的）。

自检结论（已演练）：
- 回归检测：用临时脚本先建基线再打破一条用例 → 判 `REGRESSION` + 闸门 `FAIL` + 「阻塞项」列出该用例。演练产物已删除。
- testkit 结构化块解析正确（含 `⚠` 告警不阻塞）；块内声明的 version 优先于文件名推断。
- 缺凭据路径：`--include-live` 无 `LIVE_KEY` → 记为跳过 + 闸门 `INCOMPLETE`，理由写明「缺凭据」。
